# Web3 Intelligence Radar v0.2 Backlog

v0.1 Development Freeze 期间出现的 P2/P3 记录在此。
只记录 Problem / Evidence / Priority / Decision，不提前写技术方案。
进入 v0.2 需：≥1 周 Trial Run 证据 + 用户明确批准。

## Candidate

### Data Sources

- **Problem:** Source adapters lack persistent health/freshness metrics and several configured endpoints currently return 404/429.
  **Evidence:** 2026-11-11 authenticated-network audit found Industry 11 sources / 2 failed and Competitor 48 sources / 18 failed after P1 fixes.
  **Priority:** P2.
  **Decision:** During the v0.1 trial, persist per-source success, failure reason, item count and last fresh event; replace URLs only with official-source evidence.

- **Problem:** Google Play HTML parsing cannot reliably prove version or release time.
  **Evidence:** The collector falls back to page text when structured fields are absent; weekly freshness and change identity are therefore weak.
  **Priority:** P2.
  **Decision:** Evaluate a maintained metadata provider or a source-specific parser with fixtures before treating Google Play updates as high-confidence signals.

### Competitor Coverage

- **Problem:** Competitor reports can be empty without LLM scoring even when deterministic candidates exist.
  **Evidence:** 2026-11-11 no-AI weekly audit retained 20 in-window events but produced no high-signal item under current deterministic defaults.
  **Priority:** P2.
  **Decision:** Calibrate deterministic event-type priors against one or more weeks of labeled trial data; do not raise thresholds or scores speculatively.

### Intelligence Quality

- **Problem:** Scores and summaries are not versioned against labeled outcomes.
  **Evidence:** Config records weights and model pricing, but reports do not identify a scoring-rule version or evaluation set.
  **Priority:** P2.
  **Decision:** Add rule/model version metadata and a small labeled regression corpus before claiming measurable signal quality.

- **Problem:** Provenance is URL-level rather than evidence-level.
  **Evidence:** Events keep source URL and excerpts, but not fetch timestamp, content hash, or immutable snapshot reference.
  **Priority:** P2.
  **Decision:** Define a lightweight provenance envelope before multi-source entity merging or historical backtesting.

- **Problem:** Untrusted source text is passed into LLM prompts without an explicit prompt-injection boundary.
  **Evidence:** Titles and excerpts are serialized directly into classifier and synthesis prompts.
  **Priority:** P2.
  **Decision:** Add source-content delimiters, instruction-ignore policy, output validation and adversarial fixtures; retain human-review wording.

### Delivery

- **Problem:** There is no user-level Watchlist or alert preference model.
  **Evidence:** v0.1 outputs are global Industry/Competitor reports delivered to fixed targets.
  **Priority:** P3.
  **Decision:** Consider only after trial evidence shows stable source quality and repeated team usage.

### Operations

- **Problem:** Dependency installation is not reproducible.
  **Evidence:** `pyproject.toml` uses lower bounds and CI installs latest compatible packages without a lock/constraints file.
  **Priority:** P2.
  **Decision:** Generate and test a Python 3.12 lock/constraints workflow before v0.2 development.

- **Problem:** State corruption recovery is silent and can reset dedupe/cost context.
  **Evidence:** malformed JSON is auto-initialized; Git history is recoverable but no production alert is emitted.
  **Priority:** P2.
  **Decision:** Add explicit corruption telemetry and a documented restore path; fail closed for delivery idempotency where practical.

### Secret / Infrastructure

- **Problem:** Optional Anthropic support is not installed by the default CI command.
  **Evidence:** `anthropic` is in the `llm` extra while workflows run `pip install -e .`.
  **Priority:** P2.
  **Decision:** Install provider extras only for configured roles or document the required workflow change when enabling Anthropic.
